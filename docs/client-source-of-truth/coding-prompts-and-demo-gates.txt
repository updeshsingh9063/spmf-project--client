How to use these prompts
Each ticket below is written as a standalone copy/paste instruction. It intentionally repeats the core product guardrails so scope does not drift between tickets.
The prompts assume the established SPFM technical foundation: Next.js/React frontend, ASP.NET Core API backend, Microsoft Entra/MSAL authentication direction, and a persistent database. Preserve that foundation unless a ticket or a concrete technical constraint requires otherwise.
The developer should work in a feature branch (or equivalent isolated change set), deploy a testable build, and provide evidence that the acceptance criteria pass. No ticket is considered complete merely because code has been written.
Standing instructions for every ticket
Treat the Product Requirements and Developer Backlog as controlling specifications. Where existing code conflicts with them, preserve reusable technical/UI work but implement the approved SPFM behavior.
Do not reintroduce manual job-costing, gross-margin, labor/subcontractor/overhead workflows into the Alpha unless explicitly approved in writing.
QuickBooks is the accounting system of record. Do not require users to re-key financial data that is available from QuickBooks.
Automate deterministic behavior. Surface ambiguous financial decisions to a human; do not silently guess.
Keep the Alpha deliberately narrow. Do not add dashboards, admin systems, mobile polish, CRM, manufacturing, door configuration, pricing, or weight-calculator functionality unless a ticket explicitly calls for it.
Before coding, inspect the existing implementation and state any technical conflict or ambiguity. If the issue changes product behavior, stop and ask before proceeding.
At completion, provide: changed files/components, schema/API changes, migration notes, tests run/results, deployed test URL, and known limitations.
